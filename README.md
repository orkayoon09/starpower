# 스타파워 점수 집계 웹앱

참가자가 매 교환 세션 후 자기 칩을 한 번 입력하면 점수가 자동 계산되어 진행자 화면에 바로 집계되고, 마감하면 순위대로 계급이 자동 이동합니다.
규칙은 `평등위_스타 파워` 문서(점수표, 현재 칩 기준 점수)와 10/15 회의록(칩 최대 5개)을 따릅니다.

## 어떻게 쓰나요: 두 가지 방법

| | A. Netlify에 올리기 (추천) | B. 진행자 노트북에서 실행 |
|---|---|---|
| 참가자 접속 | 링크 하나 (와이파이 무관, 데이터 접속도 가능) | 같은 와이파이 필요 |
| 준비 | 1회 배포 (약 10분) | Node.js 설치 |
| 화면 갱신 | 3~4초마다 자동 | 즉시 (실시간) |
| 데이터 | Netlify Blobs에 저장 | `data/state.json` |

## A. Netlify에 올리기

한 번만 하면 됩니다. 이후에는 링크만 공유하면 됩니다.

1. **GitHub에 올리기**: github.com에서 새 저장소(Private 가능)를 만들고, 이 폴더의 파일을 웹에서 `Add file > Upload files`로 올립니다. `node_modules`와 `data` 폴더는 올리지 마세요 (이 압축 파일에는 들어 있지 않습니다).
2. **Netlify 연결**: app.netlify.com 에서 `Add new project > Import an existing project > GitHub`로 저장소를 고릅니다. 빌드 설정은 `netlify.toml`에서 자동으로 읽으므로 그대로 `Deploy`를 누르면 됩니다.
3. **진행자 비밀번호 지정 (필수)**: `Project configuration > Environment variables`에서 `ADMIN_PASSWORD`를 추가하고 값을 정한 뒤, `Deploys > Trigger deploy`로 다시 배포합니다. 비밀번호를 정하지 않으면 진행자 로그인이 열리지 않습니다.
4. 사이트 주소(예: `https://내이름.netlify.app`)가 참가자 링크이고, 뒤에 `/admin`을 붙이면 진행자 화면입니다. `Site configuration > Change site name`에서 주소를 외우기 쉽게 바꿀 수 있습니다.
5. 진행자 `설정` 탭의 QR 코드로 참가자 링크를 화면에 띄울 수 있습니다.

GitHub 없이 올리려면 Netlify CLI를 쓸 수 있습니다: `npm install` 후 `npx netlify deploy --prod`. (이 방식은 `node_modules`가 로컬에 있어야 하지만 올라가지는 않습니다.)

**알아둘 점**

- Netlify 무료 플랜은 월 사용량 한도(크레딧)가 있고, 넘으면 사이트가 멈춥니다. 60명이 몇 시간 쓰는 정도는 여유가 있지만, 행사 전에 `Team settings > Usage`에서 남은 양을 확인하세요. 참가자 화면은 4초마다, 진행자 화면은 3초마다 서버에 물어봅니다.
- 행사 때 쓸 데이터는 처음 접속하는 순간부터 쌓입니다. 리허설 뒤에는 `설정 > 게임 기록 초기화` 또는 `모든 데이터 초기화`로 지우고 시작하세요.
- 코드를 고쳐 다시 배포해도 저장된 데이터는 유지됩니다.

## B. 진행자 노트북에서 실행

1. 진행자 노트북에 Node.js 18 이상을 설치합니다 (https://nodejs.org). 설치할 패키지는 없습니다 (`npm install` 불필요).
2. 이 폴더에서 터미널을 열고 실행합니다.

```
node server.js
```

3. 터미널에 나오는 주소와 비밀번호를 사용합니다.
   - 진행자: `http://localhost:3000/admin` (비밀번호는 터미널에 표시, 설정 탭에서 변경 가능)
   - 참가자: 터미널에 표시된 `http://192.168.x.x:3000` (진행자 `설정` 탭에서 QR 코드로도 표시)
4. 참가자 폰이 진행자 노트북과 **같은 와이파이**에 있어야 합니다. 학교 와이파이가 기기 간 통신을 막으면 노트북 핫스팟을 쓰거나 방법 A를 쓰세요.

비밀번호를 직접 정하려면 `ADMIN_PASSWORD=원하는값 node server.js`, 포트를 바꾸려면 `PORT=8080 node server.js`.
모든 데이터는 `data/state.json`에 자동 저장되어, 서버를 껐다 켜도 이어집니다.

## 반별로 따로 진행하기 (v2.0)

찾는·여는반과 꾸는반은 서로 다른 속도로 진행할 수 있습니다. 한 사이트를 쓰되, 진행자 화면이 반마다 따로 있습니다.

- **로그인**: `/admin`에서 같은 비밀번호를 입력하고, 아래 `내가 맡는 반`에서 찾는·여는반 또는 꾸는반을 고릅니다. 화면 위쪽에 맡은 반이 표시됩니다.
- **반별 독립 진행**: 집계 시작, 마감, 되돌리기, 라운드 번호, 계급 이동, 결과가 모두 반별입니다. 꾸는반이 2라운드에 들어가도 찾는·여는반은 1라운드 집계 중일 수 있고, 서로 영향을 주지 않습니다. 참가자는 자기 반의 집계 상태만 봅니다.
- **내 반만 수정**: 진행자 화면에서는 내 반 참가자와 설정(계급 정원 등)만 고칠 수 있습니다. 다른 반 명단은 보이지도 않고 수정되지도 않습니다.
- **합치기**: 쉬는시간 뒤 두 반을 합칠 때는 **양쪽 진행자가 각자 화면의 `합치기` 버튼을 모두 눌러야** 합쳐집니다. 한쪽만 누르면 상대가 누를 때까지 대기하고, 합치기를 누른 반은 집계 시작·되돌리기가 잠깁니다(`합치기 취소`로 풀 수 있음). 집계가 열려 있는 반은 마감한 뒤에 누를 수 있습니다.
- **합친 뒤**: 찾는·여는반 진행자 화면에서만 진행합니다(꾸는반 화면은 보기 전용). 라운드 번호는 두 반 중 더 큰 값에서 이어지고, 첫 통합 집계에는 순위 변화가 표시되지 않습니다. 합치기 전 기록도 결과 탭에서 계속 볼 수 있습니다. 게임 종료와 초기화도 찾는·여는반 화면에서 합니다.
- **이전 버전 데이터**: 1.x 버전에서 진행 중이던 데이터는 명단·PIN·설정은 유지하고 진행 기록(라운드, 계급 이동)은 초기화됩니다. 리허설 기록이 남아 있다면 이 기회에 정리하세요.

## 진행 순서

1. **참가자·출석 탭**: 사전 명단(이름, 생년월일, 입학시기)을 붙여넣으면 PIN(숫자 4자리)이 자동 발급되고, 출석한 사람을 나이 많은 순(같으면 입학 빠른 순)으로 세워 위 계급부터 정원만큼 채웁니다 (기본: 찾는·여는반 네모 4 / 세모 14, 꾸는반 네모 3 / 세모 10, 나머지는 전부 동그라미). 행사 당일에는 **출석 칸만 체크**하면 되고, 안 온 사람은 체크를 빼면 네모·세모 인원은 그대로 유지한 채 동그라미만 줄어듭니다. 명단에 없는 사람이 오면 `한 명 추가`로 넣으세요. 첫 집계를 시작하면 초기 계급이 고정되고, 그 뒤에 온 사람은 동그라미에서 시작합니다. `이름·PIN 명단 인쇄`로 안내문을 뽑을 수 있습니다. 참가자 표의 PIN 칸은 화면을 띄워 두고 진행할 때 노출되지 않도록 기본으로 가려져 있고, `PIN 보이기` 버튼을 누르면 보입니다(새로고침하면 다시 가려집니다).
2. 참가자는 폰에서 **이름 + 숫자 4자리**로 로그인합니다.
3. **집계 탭**에서 `집계 시작`을 누르면 참가자 화면에 입력창이 열립니다. 참가자는 손에 든 칩 최대 5개를 골라 제출하고, 마감 전까지 수정할 수 있습니다. 제출 현황과 미제출자 명단이 실시간으로 보입니다.
4. 보너스 칩은 참가자가 칩 입력 화면의 `보너스 칩` 칸에서 직접 개수를 입력합니다 (칩 1개 = 3점, 한 번에 최대 10개까지, 둘 다 설정에서 변경 가능). 진행자는 집계 표의 `보너스` 칸 +/−로 고칠 수 있고, 진행자가 입력한 값이 있으면 그 값이 우선합니다. 제출하지 않은 사람은 이전 칩과 이전 보너스 칩이 그대로 유지됩니다. 같은 칸에서 `입력/수정`으로 대신 입력할 수도 있습니다. 위쪽 ‘보너스 칩 현황’은 지금까지 입력된 보너스 칩의 반별·계급별 합계를 참고용으로 보여줍니다. 보너스 칩은 거래·양도가 되고 계급이 바뀌어도 가지고 갈 수 있어서, 계급별 정원이나 초과 경고는 없습니다.
5. `집계 마감하고 계급 이동`을 누르면 점수 순으로 순위를 매기고, 계급별 인원만큼 위에서부터 계급을 나눕니다. 점수가 같으면 공동 순위로 표시합니다. 계급별 인원은 설정에서 바꾸지 않는 한 **항상 정원 그대로** 유지되고, 동점자가 계급 경계에 걸리면 **1순위 기존 계급 유지(원래 높은 계급에 있던 사람이 먼저), 2순위 생년월일(나이 많은 순), 3순위 기수(입학 빠른 순)** 로 윗 계급 자리를 채웁니다(예: 네모 3자리에 네모 출신 3명과 세모 출신 2명이 동점이면 네모 출신 3명이 네모를 유지). 참가자 화면에는 순위·계급·점수가 뜨고, 계급이 바뀐 사람에게는 이동 안내가 표시됩니다. 순위 변화(직전 집계 대비 ▲/▼ 몇 계단, 예: 17위 → 15위)도 진행자 결과 탭과 참가자 화면에 함께 표시됩니다. 첫 집계에는 비교할 직전 순위가 없어서 표시되지 않습니다.
6. 모든 라운드가 끝나면 집계 탭의 `게임 종료`를 누릅니다(확인창이 한 번 뜹니다). 진행자 화면에 `최종 결과` 탭이 열리고, 반별 최종 계급 명단·통계 요약(진행 라운드, 계급 이동 횟수, 끝까지 같은 계급인 사람, 순위가 가장 많이 오른/내린 사람 등)·사람별 라운드 계급 이동 기록이 나옵니다. `모니터 화면으로 보기`는 이동 기록 표를 빼고 명단과 요약만 크게 보여주고, `인쇄 / PDF 저장`과 `최종 결과 CSV`로 내보낼 수 있습니다. 참가자 화면에는 각자의 최종 계급·순위·점수, 라운드별 계급 이동, 반 전체 계급 인원이 나옵니다(다른 사람 이름은 나오지 않습니다). 종료하면 집계 시작·되돌리기·명단 수정·계급 수정이 잠기고, 실수였다면 `종료 취소`로 그대로 이어서 진행할 수 있습니다. `게임 초기화`를 하면 종료 상태도 풀립니다.
6. **결과 탭**: 계급별 명단, 이동 인원(올라감 / 내려감 / 그대로), 이름표가 쌓이는 점수 분포 히스토그램, 토론 그룹(계급별 점수 절반)을 볼 수 있습니다. `모니터 화면으로 보기`는 전체 화면 표시용입니다.
7. 실수했을 때는 `마지막 집계 되돌리기`로 마감 직전 상태(제출 내용 포함)로 돌아갑니다.

## 감옥

`참가자·출석` 탭의 각 참가자 줄에서 `감옥` 버튼으로 수감하고, 같은 자리의 `석방` 버튼으로 풀어줍니다. 표 위쪽의 `전체 석방`은 내 반(통합 후에는 전체) 수감자를 한 번에 석방합니다. 수감된 참가자는 칩을 제출할 수 없고(이번 집계에 이미 낸 칩은 취소되고, 이전 칩과 점수가 유지됩니다), 순위와 계급 이동은 그대로 계산됩니다. 수감자에게는 집계 탭·결과 탭의 이름 옆에 감옥 아이콘이 붙고(결과 탭은 가장 최근 집계 기준), 본인 화면에는 `수감 중` 안내가 뜹니다. 진행자가 `입력/수정`으로 대신 칩을 입력하는 것은 막지 않습니다. 게임 종료 후에는 수감·석방이 잠깁니다.

## 집계 점검: 제출 현황, 이상 징후 알림, 점수 수정

- **제출 현황**: 집계 탭 표 위쪽의 `전체 / 제출자만 / 미제출만` 버튼으로 모아 볼 수 있습니다. `제출자만`은 최근에 낸 순서로 정렬되고, 제출 시각이 함께 표시됩니다.
- **이상 징후 알림(부정행위 의심)**: 집계 중에 제출된 내용을 직전 마감 상태와 비교해서 아래 경우에 집계 탭 위쪽에 빨간 알림 카드를 띄우고, 새로 생기면 화면 위에 안내도 한 번 뜹니다. 탭 이름에도 건수가 붙습니다. 확인한 알림은 `확인함`으로 숨길 수 있습니다(`다시 보기`로 복구).
  1. **높은 점수**: 최상위 계급(기본 네모)이 아닌 사람이 보너스 칩 없이 칩 점수가 기준(기본 20점)을 넘음
  2. **보너스 칩 총량**: 보너스 칩이 처음 지급된 라운드(반 전체 보너스 칩이 0개가 아니게 된 첫 라운드) 이후, 반(통합 후에는 전체) 보너스 칩 합계가 직전 라운드와 달라짐. 거래·양도로 사람별 개수가 바뀌어도 합계가 같으면 정상으로 봅니다.
  3. **점수 급변**: 첫 라운드와 보너스 칩 지급 라운드를 제외하고, 제출한 사람의 점수가 직전보다 기준(기본 10점) 이상 오르거나 내림
  집계 탭 맨 아래 `이상 징후 알림 설정`에서 조건마다 켜고 끌 수 있고 기준 숫자를 바꿀 수 있습니다(진행자 두 화면이 공유하는 설정입니다). 알림은 참고용이라 실제 칩과 대조해서 판단하세요.
- **집계 중이 아닐 때 점수 수정**: 집계 대기 중에는 집계 탭에 `참가자 점수` 표가 나오고, `점수 수정`에서 칩과 보너스 칩을 고칠 수 있습니다. 점수만 바뀌고 **순위와 계급은 다음 집계를 마감할 때 반영**됩니다. 직전 마감 결과(결과 탭)의 점수도 같이 고쳐지고, 다음 집계에서 제출하지 않으면 고친 값이 그대로 이어집니다. 집계 중에는 기존처럼 `입력/수정`으로 고칩니다. 마지막 집계를 되돌리면 그 집계 전 상태로 돌아가므로 점수 수정 내용도 함께 되돌아갑니다.
- **결과 탭 평균 점수**: 결과 탭 위쪽에 선택한 라운드(와 반)의 평균 점수가 표시되고, 지난 라운드에도 있던 같은 사람들 기준으로 평균이 얼마나 올랐는지/내렸는지(▲/▼)도 함께 나옵니다. 첫 라운드에는 비교할 대상이 없습니다.

## 규칙 개정 세션 대비 (설정 탭)

- **점수표**: 색상별로 1~5개 가졌을 때의 점수를 칸마다 직접 수정할 수 있습니다. 칩 최대 개수(1~10)와 보너스 칩 점수도 바꿀 수 있고, `문서 기본값으로 복원`이 있습니다. 변경은 이후 집계 마감부터 적용되며, 이미 마감된 라운드는 바뀌지 않습니다. 집계가 열려 있을 때 바꾸면, 이미 제출된 칩도 마감 시점의 점수표로 다시 계산됩니다. 칩 최대 개수를 6개 이상으로 늘리면 새 칸은 ‘5개 점수 + (n−5)개 점수’로 자동으로 채워집니다(예: 하양 6개 = 16 + 1 = 17점, 7개 = 16 + 2 = 18점). 저장한 뒤 값을 확인하고 필요하면 고칠 수 있습니다.
- **계급 이름·기호·색**: 네모/세모/동그라미를 클로버/다이아몬드/하트 등으로 바꿀 수 있습니다. 위에서 아래 순서가 계급 높낮이입니다 (기본: 네모 > 세모 > 동그라미).
- **계급 정원**: 맨 아래 계급을 뺀 위쪽 계급의 정원을 반마다 바꿀 수 있습니다. 맨 아래 계급은 ‘나머지 전원’입니다.
- **반 통합**: 집계 탭의 `합치기` 버튼을 양쪽 반 진행자가 모두 누르면 한 순위표로 합쳐집니다 (네모 7 / 세모 24 고정, 나머지는 동그라미). 자세한 흐름은 위 ‘반별로 따로 진행하기’를 보세요.
- 반 이름, 라운드 번호, 비밀번호도 여기서 바꿉니다.

## 알아둘 점

- 참가자가 입력한 칩이 실제 손에 든 칩과 같은지는 앱이 확인할 수 없습니다. 진행자가 `집계` 표의 칩 색을 훑어보거나, 의심되면 직접 수정하세요.
- 같은 이름의 참가자가 둘이면 PIN이 서로 달라야 하며, 앱이 자동으로 겹치지 않게 발급합니다.
- 생년월일은 `2008-03-14`, `2008-03`, `2008` 형식을 인식합니다. 나이는 명단을 나이순으로 배정할 때 쓰이고, 집계 결과 화면에서 같은 순위 안의 표시 순서에도 쓰입니다.
- 테스트: `node test/simulate.js` (노트북 서버), `node test/migrate.js` (예전 데이터 이전), `node test/ties.js` (동점 처리 규칙), `node test/alerts.js` (이상 징후 알림·점수 수정), `npm install` 후 `node test/simulate-netlify.js` (Netlify 함수 + 로컬 Blobs). 둘 다 61명 규모 흐름(동시 제출, 마감, 되돌리기, 점수표 편집, 반별 진행, 두 반 동시 마감, 합치기 등)을 확인합니다. Netlify 시험은 로컬 Blobs 서버가 조건부 저장을 한 번에 처리하도록 맞춰 돌립니다. 실제 Netlify에서 두 진행자가 같은 순간에 누르는 경우는 이 시험으로 확인할 수 없으므로, 리허설에서 한 번 시험해 보세요.
- 구조: `lib/`에 게임 규칙과 API가 있고, `server.js`(노트북)와 `netlify/functions/api.mjs`(Netlify)가 같은 `lib/`를 사용합니다.
- 마을 제도, 소비와 생산, 선거 같은 ‘가져가볼 수 있는 변화’는 아직 포함하지 않았습니다.
